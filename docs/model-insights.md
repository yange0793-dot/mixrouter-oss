# 模型诊断与方案

这两页不替代现有渠道、槽位、会话、压缩和 Bots 配置。

## 模型与上下文

控制台左侧「模型与上下文」(`#insights`) 有两部分，打开页面或手动刷新时读取，不在后台轮询上游。

### 模型声明与响应证据

模型列表来自本机渠道库。上下文窗口、最大输出、视觉能力和推理档位可以手工记录；没有声明就显示未知，不按模型名称推测能力。这些是**诊断元数据**，保存在数据目录的 `model-specs.json`，不会改变请求参数、模型、推理强度、客户端窗口或路由行为。

请求详情分开显示三种名称：

| 字段 | 含义 |
| --- | --- |
| `model_in` | 客户端请求的模型或槽位别名 |
| `model_out` | 这次实际发给上游的模型名 |
| `upstream_model` | 从原始上游响应中观察到的模型名；没有读到就是未知 |

上游自报值不是身份认证。名称不同也可能只是别名规范化，不能据此判定渠道造假或自动停用渠道。本版只做被动响应观察，没有行为指纹算法或自动身份评分；不会调用模型问“你是谁”，也不发送额外测试请求。响应观察不修改转发字节，不改变既有重试、历史恢复与输出屏障。

模型列表显示最近成功请求的观察结果；失败请求不能成为成功模型的证据。既有日志以渠道名称记账，同组渠道重名时无法可靠归属，因此该模型的观察结果留空。旧日志没有 `upstream_model` 时不由 `model_out` 补造。

直通流复用有界的首尾采样，转换流复用已经解析的协议事件；不为诊断额外缓存整条流。压缩正文、超长事件或采样范围外的模型字段可能无法观察，此时仍显示未知，不能解释为上游没有返回该字段。

### 上下文分类

接受并准备转发的请求在入口统计以下类别，只保存数字，不保存正文、工具名称、文件路径或技能内容：

- 系统提示与指令，包括 system / developer 消息；
- 工具定义，包括 MCP 工具的 schema 和描述；
- 工具结果；
- 对话内容；
- 图片、音频、文件等可识别的媒体载荷；
- 请求参数、JSON 结构与未归类字段。

六类字节数相加等于解析后请求的紧凑 JSON UTF-8 字节数 `serialized_bytes`。它不等于原始 HTTP 的 `bytes_in`：原请求可能带空格、换行或不同的转义形式。

`estimated_text_tokens` 是基于字节数的粗估，不是模型 tokenizer 的结果，不包含可识别媒体载荷。它不代表完整多模态 token 数，不参与账单、缓存命中率或窗口上限判断。实际输入、输出、缓存仍取原有上游 usage，显示为独立数据。

这是**客户端入站请求**的结构统计，不是每次协议转换后出站正文的逐字节统计。无法仅凭请求结构可靠区分某段文字来自哪个 skill 或哪个文件，所以不会给这些项目伪造归属或精确 token 数。

页面默认看最近 100 条内存请求，最多 500 条，不是全部历史。服务重启后内存窗口重新开始；旧记录缺少统计时显示未采集，不显示为零。分类数字随普通请求日志轮转保留，日志存储边界与既有设置一致。不会为这项功能开启响应正文归档。

### API

- `GET /api/insights/models`：登记模型、手工声明、来源和最近响应观察。
- `PUT /api/insights/models`：`{app, provider, model, expected_revision, spec}`。spec 的字段是 `context_window`、`max_output_tokens`、`vision`、`reasoning_levels`；`null` 清除相应声明。保存整份 spec，不合并旧的省略字段。陈旧修订返回 409。
- `GET /api/insights/requests?limit=100`：最近内存请求的模型名称、真实用量和分类数字。limit 为 1–500。

## 模型方案

控制台左侧「模型方案」(`#profiles`) 可把当前 Claude、Codex 或两组槽位保存成命名方案。

1. 先在既有渠道页把槽位和后备池配置好。
2. 打开模型方案，输入名称并选择保存哪些协议组。
3. 保存只创建快照，不切换当前路由。
4. 切换时先预览逐槽差异，再确认应用。预览后配置发生变化时拒绝覆盖，重新预览即可。

方案保留选中组的槽位目标、后备池、池策略与工具过滤设置。它**不包含**渠道 Key 明文、渠道生效账号、客户端设置、effort、压缩配置、Bots 或会话覆盖。删除方案只删除快照，不回退当前路由。

应用方案替换选中组的整张槽位表，未选中的组原样保留。已删除、停用或失效的目标会明确阻止应用，不静默过滤后备成员。已有会话级槽位覆盖仍优先于全局槽位，普通精确模型请求也不会因此变成槽位请求。

从**后续新请求**开始使用新全局槽位，在途请求不会中途切换。该操作不修改客户端模型选择器目录或默认模型，客户端界面的缓存名称可能暂时保持原值；服务端真实落点以请求记录为准。槽位切换本身不是让客户端改选另一个别名。

方案保存在数据目录的 `profiles.json`，最多 30 个，文件权限为 0600。文件缺失时只读显示空表，不自动创建默认方案。配置损坏或版本不受支持时明确报错，不当作空表覆盖。

macOS 外壳的菜单栏增加「切换方案」，打开菜单时读取本机方案列表，切换前仍显示差异并要求确认；不在后台轮询方案或重启服务。菜单也提供「模型与上下文」和「诊断」的快捷入口。已经安装的旧外壳需要按现有 `scripts/build-app.sh` 流程重新构建，单独更新服务源码不会替换外壳二进制。

### API

- `GET /api/profiles`：方案清单、修订号与当前槽位修订。active 按当前槽位比较，不是上一次点击记录。
- `POST /api/profiles`：`{name, apps, expected_revision}`，apps 为 `claude`、`codex` 或两者。
- `POST /api/profiles/:id/preview`：预览差异与可应用状态。
- `POST /api/profiles/:id/apply`：`{confirm:true, expected_revision, slots_revision}`。
- `DELETE /api/profiles/:id`：`{confirm:true, expected_revision}`。

## 不变的边界

- 压缩 → 槽位 → 唯一登记模型的选择顺序不因诊断或方案功能改变。
- 固定 Key、会话覆盖、后备池、重试次数/间隔/总预算与已输出不重放保持原有语义。
- 不恢复冷却、熔断、费用估算、通用匹配规则或默认回退。
- 本版未接入智能意图分类，也没有隐藏的分类器开关。现有路由没有可靠的用户回合边界；直接在会话级判断可能让工具续接、重试或子代理请求切错模型。接入还需要异步分类与取消/总预算协调，本版不为此改写核心链路，不给任何额外模型发送用户消息。
- `profiles.json` 与 `model-specs.json` 属于本机运行数据，不进入 git 或发布包。
