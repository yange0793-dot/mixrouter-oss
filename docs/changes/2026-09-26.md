## 备份池轮换:预警此前只有服务端看得见

`lib/backup/pool-watch.js`(09-20 的 `fe0275e`)能算出"这一次备份会顶掉哪几份",`backupFile`
也在 `unlink` 之前调它。但那条预警的出口只有 `console.warn`——**按按钮的那个人看不见**。
池子默认只留 5 份,轮换是常态;用户会以为备份一直在,直到需要找回时才发现最老的那份早没了。

`pool-watch.js` 文件头本来就写着「`onWarn` 收到一句人话,**调用方决定往哪儿送(控制台 / 日志 /
响应体)**」——控制台那条路一直没接。

改动:

- `mixrouter.js` 的 `backupWithWatch()` 除 `console.warn` 外,把预警**收集进返回值**。
- `switchClaude` / `switchCodex` / `switchClaudeRouter` / `switchCodexRouter` /
  `writeCodexConfig` 把 `{ warnings }` 回给调用方(`switchCodex` 原先是空返回,一并补上)。
- `/api/switch/:id` 与 `/api/router/:app` 在 200 响应体里带上 `warnings`(没有轮换就**不带**
  这个字段,免得变成每次都喊)。
- 控制台(`public/index.html`)新增 `#toast.warn` 样式与 `warnToast()` / `toastWithBackupWarnings()`:
  成功那句与轮换那句**并进同一条提示**再显示,而不是各弹一条。同一个 `#toast` 只能显示一条,
  后弹的会把"已写入配置"顶掉,用户看到的就是"操作失败了"。

**准确边界(别读成"删除前拦截")**:`backupFile` 确实在 `unlink` **之前**算预警,但 HTTP 响应
是在整个切换动作**之后**才回的。所以你在面板上看到那句话时,文件已经删了。它买到的是"当场
知道",不是"来得及另存"。要"停下来等确认"是另一件事,已列进 README「计划中」。

`lib/config-backup.js` 只加了一段注释:明确返回值里**不放**"删了哪几份"。那个集合就是
`pool-watch` 报出来的同一批,多一个出口就多一处要与它同步的口径——`pool-watch` 文件头自己
写着,报出来的与实际删的不一致是"最坏的一种报告:看着更专业,结论是错的"。

## `proxy.test.js` 的一条 socket 竞态(CI 上真实红过)

run `35510887003`(09-20,提交 `1fab3f2`)的 **Node 22 与 Node 24 两条腿**同时挂在:

```
Error: Test "灌到超出排空预算的请求被有界终止…" at test/proxy.test.js:248:1 generated
asynchronous activity after the test ended. This activity created the error
"Error: write ECONNRESET" and would have caused the test to fail, but instead
triggered an uncaughtException event.
```

成因是**测试自己的客户端**,不是服务端:3MB 请求体里没发完的那部分,在 `req` 已经 close
(其 `error` 监听的兜底随之结束)之后才撞上服务端销毁连接产生的 RST/EPIPE。此时那个 socket
的 `'error'` 没有监听者,于是变成 `uncaughtException`,把整套测试判红。用例的断言本身
(`bodyDrainAborts` 恰好 +1)不依赖客户端收到什么,所以这是纯粹的测试夹具缺陷。

修法是给客户端请求挂一个 socket 级 no-op error 监听,一行。

**实测复现与验证**(探针在 `/tmp`,未进仓库):同一个"大写入 + 服务端销毁连接"形状,
不挂 socket 处理器时 6 次里 4 次捕获到未处理异常(`EPIPE` ×3、`ECONNRESET` ×1);挂上之后 6 次全干净。

## 仍未覆盖的边界

- 上面那张注入表里,"前端忽略 warnings"一条只让 **ui** 的用例变红;`backup-api` 那两条
  验的是服务端**发了**什么,不验前端**显示**什么。两段各管一头,改前端时不能只看 backup-api 绿。
- `warnings` 只在**备份轮换**时出现。备份本身的失败(`copyFileSync` 抛错、`chmod` 抛错、
  源文件不存在返回 `null`)没有走这条通道——那些路径本来就冒泡成 500,不需要额外提示,
  但也意味着"响应里没有 `warnings`"不等于"备份一切正常"。
- Codex 一侧的响应出口这次一并接了,但没有对应的 HTTP 用例:`test/backup-api.test.js` 那条
  池满用例走的是 claude 组。Codex 组走 `writeCodexConfig`,逻辑同源,是本条覆盖缺口。
- 池满预警说的是"删除循环要删的那一批"。`unlink` 失败在这里被吞掉(单个备份删不掉不该让整次
  配置写入失败),所以极端情况下某个名字在预警里、文件却仍在盘上。这一点写在
  `lib/config-backup.js` 的注释里,没有用例覆盖。
